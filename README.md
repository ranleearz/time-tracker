# Срез

Локальный тайм-трекер: свои аккаунты, проекты, старт и стоп, ручные записи, отчёты и выгрузка CSV. Вкладки одного пользователя синхронизируются через WebSocket. Внешних API нет: браузер говорит только с вашим Express, Express — только с PostgreSQL на localhost.

## Стек

- Клиент: React 19, Vite, Tailwind 4, React Router
- Сервер: Node.js, Express 4, `pg`, Zod, bcrypt, JWT в httpOnly-cookie, `ws`
- Общие схемы и расчёт длительности: пакет `@tracker/shared`
- База: PostgreSQL 16 в Docker

## Требования

- Node.js 22 или новее
- npm 11
- Docker Desktop, если поднимаете Postgres из `docker-compose.yml`

## Запуск

Из корня репозитория:

```bash
copy .env.example .env
```

В `.env` замените оба JWT-секрета на длинные случайные строки. Строка подключения уже совпадает с compose-файлом:

```text
postgres://tracker:tracker@localhost:5432/tracker
```

Дальше:

```bash
docker compose up -d
npm install
npm run dev
```

Клиент: http://localhost:5173  
API: http://localhost:4000  

`npm run dev` поднимает сервер и Vite. Сервер сам дожидается базы и применяет SQL-миграции из `server/migrations`. Повторный запуск миграции ничего не меняет: имена файлов пишутся в `schema_migrations`.

Остановка базы:

```bash
docker compose down
```

Данные остаются в томе `tracker_pg`.

## Скрипты

- `npm run dev` — API и клиент
- `npm run test` — проверки длительности, пересечений, CSV и сборки отчёта
- `npm run build` — проверка типов сервера и сборка клиента
- `npm run db` — только контейнер Postgres

## Переменные

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | строка подключения Postgres |
| `JWT_ACCESS_SECRET` | подпись access-cookie, 15 минут |
| `JWT_REFRESH_SECRET` | pepper для хеша refresh-токена |
| `CLIENT_ORIGIN` | origin клиента для CORS, по умолчанию `http://localhost:5173` |
| `PORT` | порт API, по умолчанию `4000` |

Vite проксирует `/api` и `/ws` на API, поэтому браузер видит один origin и отправляет cookie и в HTTP, и в рукопожатие WebSocket.

## Как устроена сессия

Регистрация и вход кладут два httpOnly-cookie с `SameSite=Lax`:

- `access_token` на путь `/`, живёт 15 минут
- `refresh_token` на путь `/api/auth`, живёт 7 дней

В базе хранится только SHA-256 от refresh-токена с секретом, не сам токен и не JWT. Пароль — bcrypt. Неверный вход отвечает одной и той же ошибкой и для неизвестного email, и для неверного пароля. Каждый запрос к проектам и записям фильтруется по `user_id` из access-токена.

Если access истёк, клиент один раз вызывает `POST /api/auth/refresh` и повторяет запрос. Выход удаляет refresh-токен и чистит cookie.

## Модель данных

- `users` — email, имя, хеш пароля
- `refresh_tokens` — хеш токена и срок
- `projects` — имя, цвет из фиксированной палитры, флаг архива. Имя уникально у пользователя без учёта регистра
- `time_entries` — проект, описание, `started_at`, `ended_at`. `NULL` в `ended_at` значит, что таймер ещё идёт. Частичный уникальный индекс не даёт держать два открытых интервала. `ended_at` обязан быть позже `started_at`

Удалить проект с записями нельзя: внешний ключ вернёт ошибку, API ответит 409 и предложит архив. Архивный проект нельзя выбрать для нового таймера, старые записи на нём остаются.

Запись интервалов сериализуется по пользователю через `pg_advisory_xact_lock`, чтобы два параллельных старта не создали пересечение.

## Таймер и записи

- `GET /api/timer` — текущий открытый интервал или `null`. После перезагрузки страницы секунды считаются на клиенте от `started_at`
- `POST /api/timer/start` — если таймер уже идёт, сервер закрывает его и открывает новый в одной транзакции. Новый интервал начинается ровно в момент остановки предыдущего
- `POST /api/timer/stop` — ставит `ended_at`
- `GET /api/entries?from&to&projectId&tzOffsetMinutes` — записи, у которых старт попал в локальные сутки диапазона
- `POST /api/entries` — ручной закрытый интервал
- `PATCH /api/entries/:id` — описание, проект, границы. Пустой `endedAt: null` оставляет или снова открывает таймер
- `DELETE /api/entries/:id`

`tzOffsetMinutes` — это значение `Date.getTimezoneOffset()`. Для UTC+3 оно равно `-180`. Границы суток и группировка отчёта считаются в календаре браузера, а в базе время лежит как `timestamptz`.

Сервер отклоняет интервал, который пересекается с другим, второй открытый таймер, окончание не позже начала и время сильнее чем на минуту в будущем. Соприкосновение границ пересечением не считается.

## Проекты

- `GET /api/projects?includeArchived=true|false`
- `POST /api/projects` — `{ name, color }`
- `PATCH /api/projects/:id` — имя, цвет, `archived`
- `DELETE /api/projects/:id`

Цвета только из палитры в `@tracker/shared`.

## Отчёты и CSV

`GET /api/reports` с теми же фильтрами, что и список записей, возвращает:

- `totalSeconds` — сумма длительностей
- `byProject` — по проектам, по убыванию
- `byDay` — каждый день диапазона, включая нули
- `entries` — сами записи

Открытый таймер в отчёте длится до `now()` на сервере. Весь интервал относится к локальному дню его старта, даже если он перешёл через полночь.

`GET /api/reports/export.csv` отдаёт тот же набор колонками «Дата, Проект, Описание, Старт, Стоп, Длительность». Файл в UTF-8 с BOM, поля с запятыми и кавычками экранируются, значения, похожие на формулы Excel (`=`, `+`, `-`, `@`), получают префикс `'`.

Период не длиннее 366 дней.

## WebSocket

Адрес: `/ws`. Без валидной access-cookie соединение закрывается с кодом `4401`.

Хаб в памяти процесса группирует сокеты по `userId`. После изменения сервер шлёт всем вкладкам этого пользователя, включая ту, что сделала запрос:

- `entry.upserted` — `{ entry }`
- `entry.deleted` — `{ id }`
- `project.upserted` — `{ project }`
- `project.deleted` — `{ id }`

Тик раз в секунду по сокету не отправляется. Чужие события до другого пользователя не доходят. Пока API один процесс, хаб этого достаточно; при нескольких процессах понадобился бы общий брокер.

## Интерфейс

Экраны на русском:

- вход и регистрация
- трекер: крупный таймер, выбор проекта, описание, старт, стоп и перезапуск, записи за сегодня, ручное добавление, правка и удаление
- проекты: создание, цвет, архив, удаление
- отчёты: период, фильтр, суммы, столбцы по дням, таблица и кнопка «Скачать CSV»

Кнопки ждут ответ сервера. Сокет потом приводит остальные вкладки к тому же состоянию.

## Тесты

`npm run test` не требует базы. Проверяются чистые функции: длительность открытого и закрытого интервала, отказ при пересечении, отказ второго открытого таймера, границы суток UTC+3, CSV и сумма отчёта.
